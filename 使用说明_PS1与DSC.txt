Windows 新机配置脚本与 DSC 使用说明

零、直接执行所需的代码（先看这里）

管理员 PowerShell 中执行：

Set-Location "E:\Docs\configwenjian"
Unblock-File .\SetupNewPC_Optimized.ps1
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
.\SetupNewPC_Optimized.ps1 -Profile Developer

AI 工作站：

.\SetupNewPC_Optimized.ps1 -Profile AI -IncludePersonal -DockerSmokeTest

工程科学工作站：

.\SetupNewPC_Optimized.ps1 -Profile Engineering

逐项确认安装脚本：

Unblock-File .\Install-Applications.WithConfirmation.ps1
.\Install-Applications.WithConfirmation.ps1 -Profile Full

一、交付文件

1. SetupNewPC_Optimized.ps1
   主脚本。支持取消、状态续跑、重启门和开发环境阶段。

2. SetupNewPC_Optimized.ps1.txt
   主脚本的 UTF-8 文本副本，便于直接查看或复制。

3. SetupNewPC.WinBase.dsc.yaml
   DSC 阶段 1：Windows 基础、硬件诊断工具、
   VirtualMachinePlatform 和 Windows Subsystem for Linux 功能启用。

4. SetupNewPC.Development.dsc.yaml
   DSC 阶段 2：重启后的深度检测、WSL2、Docker Desktop 和开发工具链。

5. 对应的 .txt 文件
   YAML 文本副本，便于直接查看。

6. installfirsttwoapplications.txt
   人工安装顺序、包 ID、Python 分工和验证命令。

7. 使用说明_PS1与DSC.txt / 使用说明_PS1与DSC.pdf
   本说明及其 PDF 版本。

8. Setupnewpc.ps1
   兼容入口，会把参数转发给 SetupNewPC_Optimized.ps1。

9. Install-Applications.WithConfirmation.ps1
   逐项确认安装脚本。每个应用单独提示，只有输入 Y 才安装，支持 Profile 选择。

PS1 与 DSC 二选一执行，不要混用。兼容入口和主脚本也算同一种 PS1 路线。


二、总体架构：Windows 基础 -> 重启门 -> 开发环境

之所以采用三段式，是因为以下组件可能在启用后要求重启：

1. VirtualMachinePlatform（VMP）
2. Microsoft-Windows-Subsystem-Linux（WSL 可选功能）
3. Windows Update 或组件服务安装
4. BIOS/UEFI 中刚开启的 VT-x/AMD-V

若这些组件尚未生效，直接安装 Docker Desktop 和开发工具容易出现
“WSL 已安装但不可用”或 Docker 服务无法启动的问题。因此脚本在
Windows 基础完成后检查待重启状态，必要时保存进度并停止。

主脚本默认 -Stage Auto -Profile Developer 时会：

1. 执行 Windows 基础阶段。
2. 安装 PowerShell 7、HiBit Uninstaller 和 Core 软件。
3. 默认下载 WinUtil 到本地并执行 Standard preset。之后 Clash Verge 是第一个软件安装项：
   .\SetupNewPC_Optimized.ps1 -Profile Developer
4. 安装基础桌面软件、LibreHardwareMonitor、CrystalDiskInfo、
   CrystalDiskMark、Sysinternals Suite 和 Process Explorer。
5. 深度检测虚拟化、WSL、VMP 和 Linux 子系统功能。
6. 如果不需要重启，本轮继续执行开发环境阶段。
7. 如果需要重启，保存状态并登记一次登录时的续跑任务；重启后自动从
   Development 阶段继续。每个软件和步骤的结果都会写入 state.json。


三、适用环境

1. 推荐 Windows 11 22H2 或更高版本，x64 架构。
2. 必须联网，并具有管理员权限。
3. Microsoft Store 源必须可访问。
4. BIOS/UEFI 需要支持并启用 CPU 虚拟化。
5. 商业软件不自动安装，只保留提示。


四、PS1 快速执行

1. 在管理员 PowerShell 中进入文件目录。

Set-Location "E:\Docs\configwenjian"

2. 解除文件锁定，并只对当前进程放行脚本。

Unblock-File .\SetupNewPC_Optimized.ps1
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force

3. 直接运行。

.\SetupNewPC_Optimized.ps1

4. 如果需要自动选择阶段或只运行其中一个阶段：

.\SetupNewPC_Optimized.ps1 -Stage Auto -Profile Developer
.\SetupNewPC_Optimized.ps1 -Stage WindowsBase -Profile Engineering
.\SetupNewPC_Optimized.ps1 -Stage Development -Profile Engineering


五、PS1 Profile 与参数

1. -Profile
   Minimal、Developer、AI、Engineering、Full。默认 Developer。
   Minimal=Core；Developer=Core+Developer；AI=Core+Developer+AI；
   Engineering=Core+Developer+Engineering；Full=全部组。

2. -ExtraGroups
   在 Profile 之上追加 Core、Developer、AI、Engineering 或 Personal。

3. -IncludePersonal
   向任意 Profile 加入 Personal 软件，如 Steam、Thorium、PotPlayer。

4. -EnableWinUtil
   兼容参数。当前版本默认已经下载并执行 WinUtil Standard preset；不需要再传入。

5. -WinUtilSha256
   可选的 64 位十六进制 SHA256。提供后要求下载文件必须匹配；不提供时仍会记录本地哈希并继续。

6. -SkipWinUtil
   跳过默认的 WinUtil 下载和 Standard preset 执行。

7. -SkipWSL
   跳过 WSL/VMP 功能启用、WSL 初始化和 Docker 依赖。

8. -SkipDocker
   保留 WSL 初始化，但不安装 Docker Desktop。

9. -DockerSmokeTest
   仅在 Docker 已真正可用时执行 docker run --rm hello-world。

10. -SkipStoreApps
    不安装 ChatGPT Microsoft Store 版；OpenAI Codex 仍按 Profile 安装。

11. -SkipCondaInit
    安装/检测 conda，但不执行 conda init powershell，不改 PowerShell profile。

12. -AllowReboot
    检测到重启门后自动重启；默认询问。

13. -NoResume
    不登记登录后的自动续跑任务。

14. -NoPause
    无人值守时跳过结束暂停。

示例：

.\SetupNewPC_Optimized.ps1 -Profile Developer
.\SetupNewPC_Optimized.ps1 -Profile AI -IncludePersonal -DockerSmokeTest
.\SetupNewPC_Optimized.ps1 -Profile Engineering -SkipCondaInit
.\SetupNewPC_Optimized.ps1 -Profile Full

六、重启门与续跑

脚本检查以下状态：

1. Windows Update RebootRequired。
2. Component Based Servicing RebootPending。
3. PendingFileRenameOperations。
4. VirtualMachinePlatform 状态。
5. Microsoft-Windows-Subsystem-Linux 状态。
6. CPU 固件虚拟化、VT-x/AMD-V、SLAT、HypervisorPresent。
7. WSL 状态、WSL 版本、默认版本和已安装发行版。
8. docker.exe、com.docker.service 和 docker-users 用户组。

状态和检测报告位置：

C:\ProgramData\SetupNewPC\state.json
C:\ProgramData\SetupNewPC\virtualization-report.json
C:\ProgramData\SetupNewPC\docker-readiness.json
C:\ProgramData\SetupNewPC\python-strategy.txt
C:\ProgramData\SetupNewPC\environment-report.json
C:\ProgramData\SetupNewPC\environment-report.txt
C:\ProgramData\SetupNewPC\setup.log

state.json 的顶层状态为 Complete、CompletedWithFailures、AwaitingReboot 或
Failed。Items 下的每个软件/步骤记录包含 Name、Id、Status、Error、Attempts、
LastAttemptAt、LastSuccessAt 和 Version。重复运行时已经成功且仍存在的项目会
跳过，失败项目会重试。

自动续跑任务名称：

SetupNewPC-Resume-After-Reboot

开发环境成功后任务会被移除。


七、开发环境与 Python 分工

1. 系统 Python
   Python.Python.3.13 用于普通脚本、单文件工具和 uv 项目开发。

2. uv
   安装 astral-sh.uv，并设置：

   UV_PYTHON_PREFERENCE=system

   典型用法：

   uv init
   uv add <package>
   uv run <script-or-command>

   每个项目使用自己的 .venv、pyproject.toml 和 uv.lock。

3. conda
   Anaconda 用于科学计算、CUDA/ML、仿真和特定项目环境。

   conda init powershell
   conda config --set auto_activate_base false

   默认 python 保持系统 Python。需要使用科学计算环境时显式执行：

   conda create -n science python=3.13
   conda activate science
   conda install <packages>


八、Docker Desktop 深度检测

Docker Desktop 只在以下门禁通过后安装：

1. HypervisorPresent 或 CPU 虚拟化扩展可用。
2. VirtualMachinePlatform 状态为 Enabled。
3. Microsoft-Windows-Subsystem-Linux 状态为 Enabled。
4. 不存在待重启原因。
5. WSL 状态可用，默认版本为 WSL2。
6. Ubuntu 发行版已安装或安装成功。

安装后脚本会尝试启动 com.docker.service，并把当前用户加入
docker-users。新加入该组后必须重新登录才生效。

脚本把“安装成功”和“真正可用”分开验证：必须同时通过 docker.exe、
com.docker.service 和 docker info。只有显式使用 -DockerSmokeTest 时，
才会额外执行 docker run --rm hello-world。


九、DSC 使用：两个阶段按顺序执行

DSC 不支持在配置执行中途可靠地等待系统重启。本目录因此拆成两个
独立的 DSC 文件，不要把它们合并为一个连续配置。

阶段 1：Windows 基础

winget configure validate -f .\SetupNewPC.WinBase.dsc.yaml
winget configure show -f .\SetupNewPC.WinBase.dsc.yaml
winget configure -f .\SetupNewPC.WinBase.dsc.yaml

如果输出 REBOOT REQUIRED，请立即重启。重启后执行阶段 2。

阶段 2：开发环境

winget configure validate -f .\SetupNewPC.Development.dsc.yaml
winget configure show -f .\SetupNewPC.Development.dsc.yaml
winget configure -f .\SetupNewPC.Development.dsc.yaml

Development 配置的第一项是 RebootAndVirtualizationGate：

1. 如果仍有待重启原因，会停止并报错。
2. 如果 VMP 或 WSL 功能没有生效，会停止并报错。
3. 如果 CPU 虚拟化不可用，会停止并提示 BIOS/UEFI。
4. 只有门禁通过后，才会执行 WSL2 更新、Ubuntu 和 Docker Desktop。

如果当前系统把扩展名限制为 .winget，可复制并改名：

Copy-Item .\SetupNewPC.WinBase.dsc.yaml .\SetupNewPC.WinBase.dsc.winget
Copy-Item .\SetupNewPC.Development.dsc.yaml .\SetupNewPC.Development.dsc.winget

十一、常见问题

1. BIOS/UEFI 中虚拟化未开启
   - 开始菜单按 F2、Del、F10 或厂商热键进入 BIOS/UEFI。
   - 启用 Intel VT-x、Intel Virtualization Technology、SVM Mode 或 AMD-V。
   - 保存后重新启动，再运行 Development 阶段。

2. VMP 或 WSL 功能没有生效
   - 执行 Get-WindowsOptionalFeature -Online -FeatureName VirtualMachinePlatform。
   - 执行 Get-WindowsOptionalFeature -Online -FeatureName Microsoft-Windows-Subsystem-Linux。
   - 状态必须是 Enabled，而不是 EnablePending。

3. WSL 或 Docker 失败
   - 先完成所有 Windows Update 和重启。
   - 执行 wsl --update。
   - 执行 wsl --set-default-version 2。
   - 执行 wsl --install -d Ubuntu --no-launch。
   - 如果 Docker 用户组刚修改，重新登录后执行 docker info。

4. WinUtil Standard preset 失败
   - 检查网络能否访问 christitus.com 和 GitHub。
   - 检查管理员权限。
   - 使用 -SkipWinUtil 跳过，或手动执行：
     .\SetupNewPC_Optimized.ps1 -Profile Developer

5. 系统 python 被 conda 覆盖
   - 重新打开终端，检查 Get-Command python 的 Source。
   - conda base 自动激活已关闭。
   - 需要使用科学计算时显式执行 conda activate <env>。

6. 脚本等待重启但用户选择稍后
   - 状态文件仍为 AwaitingReboot。
   - 重启并登录后，续跑任务会继续；也可手动再次运行 -Stage Auto。


十二、安全与维护

1. 执行前审查 PS1、DSC YAML、第三方软件许可和下载来源。
2. 建议在虚拟机或可恢复环境中先验证。
3. WinUtil 会先下载到本地并执行 Standard preset；如不希望执行，请使用 -SkipWinUtil。可选 -WinUtilSha256 用于固定检查。
4. 企业环境应先检查代理、证书、源策略和许可证。
5. 不要把此配置用于域控制器、生产服务器或他人设备。
