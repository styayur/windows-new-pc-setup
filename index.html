00 / COMMANDS

直接执行所需的代码

需要输入的命令放在最前面。默认会下载本地 WinUtil 并执行 Standard preset，然后从 Clash Verge 开始安装。

管理员 PowerShell
Set-Location "$env:USERPROFILE\Downloads"
Unblock-File .\SetupNewPC_Optimized.ps1
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
.\SetupNewPC_Optimized.ps1 -Profile Developer

# 逐应用确认安装
Unblock-File .\Install-Applications.WithConfirmation.ps1
.\Install-Applications.WithConfirmation.ps1 -Profile Full
跳过 WinUtil 使用 -SkipWinUtil。如需固定校验，可增加 -WinUtilSha256 <64-hex-hash>。

意义：减少重复记忆，保留可审查的边界。

自动化不是为了“无人值守装完一切”，而是让环境搭建可重复、可比较、可修改。PS1 适合首次部署和需要人工确认的步骤；DSC 适合描述目标状态、验证差异和后续补装。两者共同把“装过什么、为什么这样装、如何再次复现”留在仓库里。

01 / OVERVIEW

先选路线，再执行

PS1 与 DSC 都覆盖同一批软件和环境，但控制方式不同。首次装机建议用 PS1；需要可测试、可重复补装的场景建议用 DSC。

维度PowerShell PS1DSC v3 YAML
执行模型按顺序执行，方便插入交互步骤声明目标状态，由资源测试并应用
适合场景首次新机、Profile 选择与重启续跑补装、重复执行、状态校验、配置审查
可读性逐条命令直观，容易边看边改资源边界清晰，适合版本管理和差异比较
幂等性WinGet 部分较稳定，脚本步骤可能重复执行软件包资源可测试；命令资源通常每次执行
推荐入口SetupNewPC_Optimized.ps1（Auto）先 SetupNewPC.WinBase.dsc.yaml，重启后 SetupNewPC.Development.dsc.yaml
最简单的判断 新机第一次装：选 PS1。需要先看系统是否符合目标状态、只补缺失项：选 DSC。不要为了“更完整”而同时执行两份配置。
02 / PREPARE

执行前准备

先确认系统、权限、网络和可恢复性。真正耗时的通常不是下载，而是权限、重启和后续人工配置。

  1. 使用可恢复环境。推荐 Windows 11 22H2 或更高版本、x64 架构，并在虚拟机、快照或新机恢复点中先验证。
  2. 打开管理员终端。使用“终端（管理员）”或“PowerShell（管理员）”。脚本自身会请求 UAC，但提前提权可以减少中断。
  3. 检查 WinGet。运行 winget --version。DSC v3 路线建议 WinGet 1.11 或更高版本。
  4. 更新系统与 Store。先更新 Windows、Microsoft Store 和应用安装程序，避免旧版 WinGet 或源缓存问题。
  5. 确认网络与虚拟化。WSL2 和 Docker 需要网络、虚拟化支持，通常还需要重启；企业代理环境要提前配置证书和源策略。
  6. 审查软件许可。脚本会安装第三方软件。仓库只记录安装方式，不授予任何商业软件许可。
先做三项检查
whoami /groups | findstr /i "S-1-5-32-544"
winget --version
Get-ComputerInfo | Select-Object WindowsProductName, WindowsVersion, OsArchitecture
03 / QUICKSTART

快速开始

选择一种路线，复制命令前先确认当前目录和文件名。PS1 默认自动处理基础、重启门和开发环境；DSC 必须按两个文件分阶段执行。

首次新机部署（默认 Auto）

管理员 PowerShell
Set-Location "$env:USERPROFILE\Downloads"
Unblock-File .\SetupNewPC_Optimized.ps1
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
.\SetupNewPC_Optimized.ps1 -Profile Developer

如果只有 SetupNewPC_Optimized.ps1.txt，先复制内容并另存为 .ps1。PowerShell 不会直接执行 .ps1.txt。默认 Profile 为 Developer；若 WSL/VMP 要求重启，脚本会登记登录续跑任务并自动进入 Development 阶段。

阶段 1：Windows 基础

管理员 PowerShell
Set-Location "$env:USERPROFILE\Downloads"
winget configure validate -f .\SetupNewPC.WinBase.dsc.yaml
winget configure show -f .\SetupNewPC.WinBase.dsc.yaml
winget configure -f .\SetupNewPC.WinBase.dsc.yaml

# 若输出 REBOOT REQUIRED，先重启；然后执行阶段 2
winget configure validate -f .\SetupNewPC.Development.dsc.yaml
winget configure show -f .\SetupNewPC.Development.dsc.yaml
winget configure -f .\SetupNewPC.Development.dsc.yaml

Development 配置的首个资源会再次检查待重启、VirtualMachinePlatform、WSL 功能和 CPU 虚拟化；门禁未通过时不会继续安装 Docker。

04 / PS1

PowerShell 路线

PS1 按 Windows 基础、重启门、开发环境三个阶段执行。它保存状态、刷新 PATH、设置 Java/Python/conda 策略，并在结束时执行版本检查。

常用参数

参数作用适用情况
-Profile选择 Minimal、Developer、AI、Engineering 或 Full按机器用途控制软件组
-ExtraGroups在 Profile 上追加 Core、Developer、AI、Engineering、Personal需要临时补充某一组
-Stage Auto默认；按状态自动执行基础、重启门和开发环境首次运行和重启后续跑
-Stage WindowsBase只运行 Windows 基础与 WSL/VMP 功能启用先完成系统基线，稍后重启
-Stage Development只运行重启后的开发环境手动控制第二阶段的执行时机
-WinUtilSha256可选的固定 SHA256 校验需要锁定 WinUtil 下载内容
-SkipWinUtil跳过默认的 WinUtil 下载与 Standard preset 执行不希望执行第三方在线脚本
-SkipWSL跳过 WSL/VMP、WSL 初始化及 Docker 前置依赖不开发 Linux 环境，或暂时不能重启
-SkipDocker保留 WSL 初始化，但不安装 Docker Desktop暂不需要容器环境
-SkipCondaInit保留 conda 检测，但不修改 PowerShell profile不希望修改当前用户 profile
-DockerSmokeTestDocker 已可用时执行 hello-world Smoke Test需要端到端验证容器运行时
-SkipStoreApps不安装 ChatGPT Microsoft Store 版Store 不可用、没有账号或不需要该应用
-AllowReboot检测到重启门时保存状态并自动重启可无人值守的新机或测试虚拟机
-NoResume不登记登录时的自动续跑任务不希望修改计划任务，重启后手动继续
-NoPause结束时不等待 Enter远程终端、脚本化运行或需要直接关闭窗口

组合示例

Profile 组合示例
.\SetupNewPC_Optimized.ps1 -Profile AI -DockerSmokeTest
.\SetupNewPC_Optimized.ps1 -Profile Engineering -SkipCondaInit
.\SetupNewPC_Optimized.ps1 -Profile Full

执行阶段

  1. Windows 开始：下载本地 WinUtil 并执行 Standard preset；之后 Clash Verge 是第一个软件安装项。
  2. 安装 7-Zip、Clash Verge、Git、GitHub CLI、Chrome、Listary、Steam、Logseq、Notepad3、CC Switch、PixPin、PotPlayer、Thorium。
  3. 安装 LibreHardwareMonitor、CrystalDiskInfo、CrystalDiskMark、Sysinternals Suite 和独立 Process Explorer。
  4. 启用 VirtualMachinePlatform 与 Microsoft-Windows-Subsystem-Linux，并深测固件虚拟化、VT-x/AMD-V、SLAT、HypervisorPresent。
  5. 重启门：保存 state.json；需要时登记登录续跑任务，重启后自动进入 Development。
  6. 开发环境：检查 WSL2 门禁，更新 WSL、安装 Ubuntu，并只在检查通过后安装 Docker Desktop。
  7. 按 Profile 安装 AI、Developer 和 Engineering 组软件；Developer 组包含系统 Python、uv、Node.js、VS Code、Java、Go、Rust、GCC、Postman、DBeaver。
  8. 安装 OpenJDK 21、Go、Rustup、WinLibs MinGW；配置 UV_PYTHON_PREFERENCE=system，并关闭 conda base 自动激活。
  9. 输出失败清单、虚拟化报告、Python 策略和版本验证结果。
日志位置 C:\ProgramData\SetupNewPC\setup.log。状态、虚拟化和 Docker 报告位于同一目录。若某个包失败，先查看日志中的 WinGet 退出码，再处理网络、Store 或权限问题。
05 / DSC

DSC v3 路线

YAML 把机器状态写成资源。由于 WSL/VMP 可能要求重启，配置拆成 WindowsBase 和 Development 两个文件；第二阶段的首个资源是虚拟化与重启门禁。

推荐流程

WinGet 调用 DSC v3：两个阶段
# 阶段 1：Windows 基础与 WSL/VMP 功能启用
winget configure validate -f .\SetupNewPC.WinBase.dsc.yaml
winget configure show -f .\SetupNewPC.WinBase.dsc.yaml
winget configure -f .\SetupNewPC.WinBase.dsc.yaml

# 如果输出 REBOOT REQUIRED，先重启
winget configure validate -f .\SetupNewPC.Development.dsc.yaml
winget configure show -f .\SetupNewPC.Development.dsc.yaml
winget configure -f .\SetupNewPC.Development.dsc.yaml
winget configure list

独立 DSC CLI

安装并验证 DSC v3
winget install --id Microsoft.DSC -e --source winget --accept-source-agreements --accept-package-agreements
dsc --version
dsc resource list Microsoft.WinGet/Package
dsc resource list Microsoft.DSC.Transitional/RunCommandOnSet
dsc config test --file .\SetupNewPC.WinBase.dsc.yaml
dsc config set --file .\SetupNewPC.WinBase.dsc.yaml
# 重启后
dsc config test --file .\SetupNewPC.Development.dsc.yaml
dsc config set --file .\SetupNewPC.Development.dsc.yaml
Resource 不可用怎么办 如果独立 dsc 查不到 Microsoft.WinGet/Package，不要强行修改资源名。优先更新 WinGet 和 App Installer，并使用 winget configure；它会自动使用 dscv3 处理器。

YAML 结构

DSC v3 文档骨架
$schema: https://raw.githubusercontent.com/PowerShell/DSC/main/schemas/2023/08/config/document.json
metadata:
  winget:
    processor:
      identifier: dscv3
resources:
- type: Microsoft.WinGet/Package
  name: Example
  properties:
    id: Publisher.Package
    source: winget
    useLatest: true

行为说明

  • validate 只检查文档结构，不应用机器状态。
  • show 展示解析后的资源，可用于确认包和依赖是否正确。
  • test 比较系统状态；命令资源没有测试能力时通常会显示需要执行。
  • configure -f 或 dsc config set 才真正应用资源。
  • dependsOn 保证先决条件，例如 WSL 门禁先于 Docker、OpenJDK 先于 JavaHome。
  • WindowsBase 只启用功能并要求重启；Development 在重启后验证功能状态，再安装 Docker Desktop。
06 / CUSTOMIZE

自定义方法

最安全的修改顺序是：先改单个资源，再运行校验，最后在虚拟机中测试。不要把多个未知变化一次合并后直接用于新机。

添加一个 WinGet 软件

先确认包 ID：winget search --id Publisher.Package --exact。PS1 中把 ID 加入对应数组；DSC 中复制一个资源块并修改唯一的 name。

DSC：新增软件
- type: Microsoft.WinGet/Package
  name: MyPackage
  properties:
    id: Publisher.Package
    source: winget
    useLatest: true
  metadata:
    description: 安装自定义软件

固定版本

需要可复现版本时，删除 useLatest，改用 version。版本号必须真实存在，固定版本会增加后续维护成本。

DSC：固定版本
  properties:
    id: Publisher.Package
    source: winget
    version: 1.2.3

删除或跳过软件

PS1
从 $windowsBaseApps 或 $developmentApps 数组中删除该 ID；重新运行前同时检查是否被其他步骤依赖。
DSC
删除以 - type: 开始的整个软件块。若其他资源通过 dependsOn 引用它，必须同时删除或改写依赖。
跳过 WinUtil
PS1 默认执行 WinUtil；使用 -SkipWinUtil 跳过。DSC 默认路径不执行 WinUtil。
跳过 Store
PS1 使用 -SkipStoreApps；DSC 删除 name: ChatGPT 的资源块。

修改 Java 版本

把 OpenJDK 资源替换成目标 JDK 包，例如 Microsoft.OpenJDK.17。保留后面的 JavaHome 资源，它会从当前 java.exe 反推出安装目录并设置系统变量。

多 JDK 共存时 Get-Command java.exe 只会解析当前 PATH 中最先出现的版本。需要多版本切换时，建议额外使用 SDKMAN、jEnv 或自建目录结构，不要只依赖一个 JAVA_HOME。

执行自定义命令

当 WinGet 软件资源不能表达安装参数时，可以用 RunCommandOnSet 调用明确的可执行文件。参数使用数字字符串键，并设置 treatAsArray: true。

DSC：执行自定义命令
- type: Microsoft.DSC.Transitional/RunCommandOnSet
  name: MyCommand
  properties:
    executable: C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
    arguments:
      "0": -NoProfile
      "1": -ExecutionPolicy
      "2": Bypass
      "3": -Command
      "4": |
        Write-Host "在这里写自定义步骤"
      treatAsArray: true
  metadata:
    description: 执行自定义配置

修改安装范围或安装参数

Microsoft.WinGet/Package 只暴露 id、source、version 和 useLatest。如果需要 --scope machine、--override 或静默参数，需要新增一个 RunCommandOnSet，直接调用 winget.exe；同时要自己处理重复执行和退出码。

提交前校验

每次修改后至少执行
winget configure validate -f .\SetupNewPC.WinBase.dsc.yaml
winget configure validate -f .\SetupNewPC.Development.dsc.yaml
git diff -- .\SetupNewPC.WinBase.dsc.yaml .\SetupNewPC.Development.dsc.yaml .\SetupNewPC_Optimized.ps1
07 / SAFETY

安全边界

这是一套具有管理员权限的装机配置。能减少手工操作，也会把错误集中放大。

远程脚本风险 WinUtil 默认先下载到本地并执行 Standard preset；如不需要，使用 -SkipWinUtil。可选 -WinUtilSha256 固定校验；DSC 默认路径不包含该远程脚本。
  • 先审查仓库中的 PS1、YAML 和第三方软件许可，再运行任何命令。
  • 不要把密码、API Key、代理凭据、证书私钥写入仓库。
  • 企业设备先确认软件白名单、代理、TLS 检查、区域和许可政策。
  • 不要在域控制器、生产服务器或他人设备上直接执行。
  • 先建立还原点或虚拟机快照；WSL、Docker、驱动和系统优化可能需要重启。
  • 固定版本提高可复现性，但不会自动解决上游撤包、链接失效和许可证变化。
08 / TROUBLESHOOT

故障排查

先判断问题属于 YAML、WinGet 源、权限、网络还是重启状态。不要在不了解错误时反复重试全部安装。

现象优先检查处理方式
winget 不存在App Installer、Windows 版本、PATH更新 Microsoft Store 和应用安装程序，重新打开终端
找不到程序包包 ID、源、网络执行 winget source update，再用 winget show --id ... -e 检查
YAML 校验失败缩进、冒号、Tab、资源字段只使用空格，确认 resources 下每个条目从同列开始
Store 安装失败账号、区域、Store 网络登录 Store，或删除 ChatGPT 资源并使用 -SkipStoreApps
WSL 或 Docker 失败Virtualization、VirtualMachinePlatform、WSL 功能、待重启状态开启 BIOS/UEFI 虚拟化，确认两个功能为 Enabled，重启后执行 Development 阶段
Docker 被跳过WSL 门禁或重启状态检查 C:\ProgramData\SetupNewPC\docker-readiness.json，修复后重新执行 Development
Docker 用户组刚变更docker-users 登录令牌注销并重新登录，再执行 docker info
脚本被阻止执行策略、Zone.Identifier使用 Unblock-File 和当前进程级 Bypass
版本命令找不到当前会话 PATH关闭并打开新 PowerShell；仍失败时检查系统 PATH
DSC 第一阶段后直接执行第二阶段失败REBOOT REQUIRED、EnablePending先重启并确认 VMP 和 WSL 功能均为 Enabled，再运行 Development 配置

09 / MAINTAIN

维护与发布

把配置当作代码维护：修改前看差异，修改后做校验，发布前在干净环境测试。

  1. 定期执行 winget source update，确认包 ID 和上游版本仍然存在。
  2. 更新软件列表或资源结构后，先执行 winget configure validate，再提交 Git。
  3. 把稳定版本、重大变化和安全修复写进提交信息，必要时建立 Git tag。
  4. GitHub Pages 直接托管仓库根目录的 index.html。修改后推送到 main 即可触发更新。
  5. 如果页面链接或说明发生变化，同时更新 README、TXT 和 PDF，避免多处内容漂移。

仓库更新命令

在本仓库目录执行
git status
git add .
git commit -m "Update setup documentation"
git push
