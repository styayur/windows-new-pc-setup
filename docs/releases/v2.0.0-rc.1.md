# Whinset v2.0.0-rc.1

**Release candidate.** This is not the final v2.0.0 certification. Real clean-VM UAC, privileged installer, Windows feature and reboot-continuation acceptance remains pending.

## Read before download

Whinset can install software and make machine-level changes. Review this before running `beatwin.txt` or applying a plan.

- **Elevated operations may:** install machine-scoped packages, enable Windows optional features, install/update WSL and Ubuntu, install Docker Desktop, and set machine `JAVA_HOME`/`PATH`.
- **User operations may:** configure Git LFS, uv, Conda, Go, Rust and user PATH/environment values.
- **UAC:** `apply` requests one normal Windows UAC authorization when elevated work remains. All elevated operations are then grouped into one worker. UAC is never bypassed or disabled.
- **If UAC is denied:** the elevated phase does not start; status is `ElevationDenied` and exit code is 4.
- **Restart:** some installers/features can require a restart. Whinset exits 3010 and waits for a manual restart; it does not schedule or force one.
- **Rollback:** package uninstalls can be manual but are not guaranteed to restore every vendor registry/PATH/service change. Windows features, WSL distributions and Docker state require manual review. **No automatic rollback is claimed.**
- **Logs:** `%LOCALAPPDATA%\Whinset\v2`. The bootstrap's temporary download folder is removed after the command, but permanent state/logs remain.

## What is new

- New canonical `whinset` PowerShell module/CLI and copy-paste `beatwin.txt` bootstrap.
- Schema 2 package catalog with exact Source:Id identities, vendors, architecture, scope, version policy, stage, privilege, dependencies, conflicts, expected state and recovery metadata.
- Exact stable-key/Source:Id resolution; display names are never install selectors.
- Deterministic dependency DAG planning with stable ordering, cycle/conflict validation and plan hashes.
- Separate plan and apply workflows with human and JSON output.
- One-UAC elevated worker; user-level configuration remains in the user process.
- Trusted plan reconstruction from the installed catalog instead of arbitrary elevated code.
- Resumable state, operation-level JSONL logs, reboot gates, package rechecks and exit 3010.
- Read-only discovery of legacy SetupNewPC state.
- PowerShell 7 primary support plus Windows PowerShell 5.1 regression coverage.
- Tab completion for commands, profiles, groups, stages and package keys.
- Deterministic release archive plus pinned SHA-256 bootstrap generation.

## Commands

```powershell
whinset plan -Profile Developer
whinset apply -Profile Minimal -AcceptAgreements
whinset status
whinset doctor
whinset resolve chrome
whinset recover -Retry
```

## Exit codes

`0` complete, `1` operation failure, `2` invalid input/agreement, `3` compatibility cancellation, `4` UAC denied, `5` doctor unhealthy, `3010` restart required.

## Known limitations

- Custom catalogs are plan-only in rc.1.
- The legacy WinUtil path remains available only through the legacy script and was not moved into the new elevated worker.
- Docker Desktop first-run setup and daemon startup can require manual action.
- Package inventory and installer behavior still depend on WinGet sources, Store policy, network access and vendor installers.
- Mocked tests cover orchestration, DAG ordering, UAC denial, already-elevated flow, resume and logging; they do not certify every real installer.
- Clean Windows 11 VM acceptance must be completed before publishing final v2.0.0. Current evidence is in `docs/acceptance/windows-v2.0.0-rc.1.md`.

## Verification

The release archive is built by `scripts/Build-Release.ps1`. `beatwin.txt` pins the `v2.0.0-rc.1` archive SHA-256 and is published both as a repository file and release asset. Compare it with `SHA256SUMS.txt` on the release page.
