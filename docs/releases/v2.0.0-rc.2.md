# Whinset v2.0.0-rc.2

Release candidate only. Stable remains prohibited pending independent real Windows 11 acceptance. Roadmap Issue #8 remains open.

## Read before download

Whinset can install exact catalog packages, enable Windows features, update the machine WSL runtime, install Docker Desktop and change machine JAVA_HOME/PATH. Original-user work includes package/user environment configuration, WSL distribution registration and Docker daemon/hello-world verification. Installers may modify services, registry, startup entries, PATH and files beyond Whinset's state records. Review the plan and licenses before `apply -AcceptAgreements`.

Normal Windows UAC is required when elevated work remains. Different-user UAC credentials are unsupported and rejected. Start from the intended account and use same-user elevation. No credentials are collected and UAC is never bypassed. No automatic reboot or rollback is implemented. Restart-required work exits 3010 and waits for a manual reboot. State/logs remain under `%LOCALAPPDATA%\Whinset\v2`.

## Changes since RC.1

- Original/elevated SID policy, private run ACL validation and state identity/operation checks.
- Native ERROR_CANCELLED (1223) classification; localized text no longer decides denial.
- Expiring requests, atomic single-use nonce claims, result nonce/run/hash/process-exit validation and stricter trusted graph reconstruction.
- Fixed the worker entrypoint to call its private function inside module scope.
- Separated machine WSL updates from original-user distribution registration, and Docker machine installation from original-user daemon/smoke checks.
- Rechecked interrupted installers before retry and successful packages during reconciliation; cleared reboot flags only after a boot-ID change.
- PowerShell remains the execution core. CMD remains official; Git Bash and Nushell are experimental forwarding adapters. UTF-8 JSON stdout and human-error stderr are tested across shells.
- Added security/recovery, shell, static-analysis, catalog/module, reproducibility and SHA-256 CI with machine-readable evidence. Added an actual disposable-runner package component install/recheck.

## Evidence and limits

Runtime evidence at `3d2af4ca538559d7023f8ed16a2dce17f614e9a2`:

- PowerShell 5.1 and 7 CI passed legacy, Whinset and hardening suites; the hardening suite has 19 deterministic checks on each host.
- Read-only CI shell tests passed for PowerShell 5.1/7, CMD and Git Bash. Nushell was unavailable in hosted CI; local Nushell 0.116.1 passed alongside the other shells (21 local checks including module validation).
- A fresh Notepad3 installation and repeated AlreadyInstalled verification actually passed on a disposable hosted Windows runner. This is package-component evidence, not Windows 11 CLI/UAC/reboot certification.
- Real UAC approval/denial, different-user credential rejection, clean Windows 11 multi-package apply, reboot continuation, WSL original-user first run, Docker first run/hello-world and vendor manual recovery are NOT RUN.

See `acceptance-matrix.json`, `docs/acceptance/windows-v2.0.0-rc.2.json` and `tests/VM-CHECKLIST.md`. PASS for deterministic orchestration does not certify the corresponding interactive test. BLOCKED means the required interactive environment is unavailable; it does not mean the test passed.

## Assets and recovery

`Whinset-v2.0.0-rc.2.zip`, `beatwin.txt` and `acceptance-matrix.json` are covered by `SHA256SUMS.txt`. The archive has fixed ZIP metadata and normalized text; rebuilding the same tree must yield the same SHA-256. The bootstrap pins only the RC.2 release URL/hash and defaults to plan mode. A draft asset URL becomes downloadable only after the RC.2 prerelease is published.

Published RC.1 tag/assets are preserved. RC.2 changes the plan identity; inspect old RC.1 state/logs and create a fresh RC.2 plan to reconcile installed packages. Do not rewrite an RC.1 plan hash to force recovery. Foreign-writable or inconsistent state is rejected for manual inspection. Request markers and atomic-write backups are retained as evidence. No automatic rollback is claimed.

Exit codes remain: 0 complete, 1 operation/worker failure, 2 input/agreement error, 3 compatibility cancellation, 4 UAC denied, 5 doctor unhealthy, 3010 restart required. Native/process diagnostics remain in structured logs.
